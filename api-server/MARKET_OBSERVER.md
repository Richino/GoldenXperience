# Live market observer

The practice-only observer joins the recorder, movement measurements and pattern engine. It runs independently of order execution. Analyze saves a new server-generated plan version. A signal reaching TRIGGERED never submits an order; the existing entry-review workflow still requires the trader's action.

## Phase 4: market-state engine

Phase 4 is the deterministic interpretation layer in `src/market-state.ts` (version `market-observer@2`). It consumes the Phase 2 movement measurements and Phase 3 pattern/candle context. It returns an evidence-linked H1/H4 lean, distinct 30-second quote pressure, pattern observations, spread/news/data blockers and conditions that would change the read. It is connected to the shared observer API, chart bubble and saved-plan entry gates. Patterns remain descriptive evidence; their names do not vote a trade into existence.

The pressure read distinguishes an uncovered window (`unknown`) from a covered window without persistent direction (`range`). Its settled direction and its currently observed candidate are separate fields. Direction changes need three seconds of persistence and then advance the read revision, allowing event-based AI highlights to refresh within their existing budget. Lost pressure or H1 coverage clears the corresponding read immediately. New entry signals remain blocked while the 30-second window warms. The bubble shows quote-pressure evidence alongside the closed-candle lean.

Phase 4 does not provide durable raw tick archiving, calibrated signal evaluation or automatic learning. Its mechanisms can be tested while the market is closed; its usefulness needs prospective observations. Phase 5 adds the prose interpretation described below.

## Runtime

- `MARKET_OBSERVER_ENABLED=true` (default with practice credentials) enables movement and pattern context for the fourteen featured pairs, in addition to explicitly configured stream pairs. Set it to false to retain standalone Analyze.
- Every received broker quote enters the existing movement/pattern engines. State calculation runs every 250 ms; the chart reads the shared observer about once a second. This is OANDA's sampled stream, not every transaction in the forex market.
- M1, M5 and M15 broker candles refresh each minute; H1/H4 and the economic calendar refresh every five minutes. Candle confirmation therefore has REST-refresh latency. Forming quote previews cannot become a closed-candle confirmation.
- The directional lean describes the last twenty closed trading bars on H1, with H4 alignment and distinct 30-second quote pressure. Trading-bar context retains history across session gaps; geometric patterns never bridge a missing candle interval. Velocity, efficiency and persistence describe observations, not buy/sell order flow.
- The initial engineering thresholds require 0.3 closed-candle efficiency and half a mean true range of net movement for a directional lean. Quote pressure requires a covered 30-second window, 0.35 efficiency and 0.5 pips net. Direction changes persist for three seconds. None of these thresholds establish a trading edge.
- Missing or stale quotes, H1/H4/execution context, unknown calendar coverage, high-impact pair news from 30 minutes before through 15 minutes after release, and wide spreads block new signals. The spread limits are 5 pips or 30% of M1 mean true range with a one-pip floor. News and spread restrictions do not erase observations of a previously triggered hypothetical signal.

## Plans and journal

Apply `npm.cmd --workspace api-server run db:migrate` before enabling monitoring. Migration 054 adds separate observer plans and events. It changes no existing strategy or trade tables.

Normal plans use a new M5 closed candle; Swing plans use H1. A priced plan freezes the existing Analyze V2 entry zone, entry reference, stop and target. The trigger boundary is the last closed execution candle's high plus 0.1 pip for a long, or low minus 0.1 pip for a short. The entire confirming candle must start after plan creation. Confirmation remains usable for one following execution interval, while the executable ask (long) or bid (short) must enter the frozen zone within 25% of the original stop distance from the entry reference. This additional monitoring trigger is an experimental rule, not a validated improvement to Analyze V2.

Plans move through WATCHING, READY, TRIGGERED, PAUSED and INVALIDATED/EXPIRED/CLOSED. Normal entry lifetime expires after four hours and Swing after forty-eight (or the analyzer's explicit lifetime). A missing execution plan becomes a watch condition with nullable levels; it cannot trigger. Completed versions and state changes remain in PostgreSQL. A disconnected/restarted observer cannot reconstruct an intervening path: triggered signals close with `unknown_after_gap` instead of invented wins/losses. Observed stop/target outcomes describe executable quote crossings; they are not fill-adjusted trading results.

The journal serializes writes, retains rapid transitions before flushing, refuses stale writes to terminal plans, pauses new signals while storage is unavailable and bounds its pending event backlog. API reads and mutations require the existing owner session.

## Phase 5: AI interpretation and chart bubble

`MARKET_OBSERVER_AI_ENABLED=true` (default when the existing OpenAI key is available) lets the configured analysis model explain the measured lean, quote-pressure relationship, patterns and blockers in two or three short sentences. The Responses API uses a strict JSON schema and `store: false`, retaining the existing configured model. The prompt receives measured facts, not account data, private plans or executable prices. News titles are data rather than instructions. Existing Analyze explanations remain available in the analysis card.

Server validation requires unchanged direction fields, known unique evidence IDs, the required hourly/pressure/conflicting-timeframe facts and the first blocker when present. It rejects unrecognized fields, numbers in prose (except timeframe names), forecasts, probabilities, trade instructions and unsupported order-flow language. It selects a watch condition from the engine's existing list. Every accepted result carries the original cited facts and their observation timestamp. These structural and language checks reduce errors; they cannot prove semantic faithfulness of every generated sentence. Users can expand the evidence to assess an interpretation. See the [official Structured Outputs guide](https://developers.openai.com/api/docs/guides/structured-outputs) for the API contract and its limitations.

There is one AI request in flight globally, a 90-second per-pair cooldown, a maximum of twenty calls per hour and a five-minute context refresh. Only recently viewed pairs and active plans request interpretation, after pressure coverage warms; mathematical measurements continue without AI. A pending call, disabled model, exhausted budget, timeout, refusal, incomplete response or rejected output leaves a clearly labeled rule-based explanation. A changed read immediately replaces old prose with current measured text, and an answer for an older revision cannot attach to the newer read. No provider call occurs for paused feeds. Requests and evidence are frozen at dispatch time. AI calls never run for each tick and never mutate a plan or place an order.

The web chart's Analyze button opens the mascot's **Analysis chat** immediately and saves a monitored plan. Changing the chart pair and clicking Analyze adds that pair to the same conversation (up to twelve monitored pairs). The bubble is initially absent until Analyze is used. Each message has a pair label, observation time and measured/AI source. Directional guidance describes a conditional continuation/pullback scenario, the frozen trigger, stop, target, invalidation and expiry when available; unknown or paused observations do not invent a direction.

The client polls subscribed pair snapshots once per second while visible. This is the presentation cadence; server quote/timer mathematics still run independently. Messages append for read/pressure/pattern changes, plan transitions and new validated AI explanations. Routine read changes coalesce with a ten-second cooldown, while feed state and plan transitions bypass it. Journal events retain rapid trigger/close transitions between screen polls. Repeated timestamps, unchanged reads and repeated explanations do not generate messages. The latest 120 messages belong to the current mounted chart session; reload/navigation away clears the chat transcript, while server plans and journal events remain durable. Earlier messages keep their original evidence and are not rewritten from new reads. Transcript messages from several pairs do not change the selected pair's detailed evidence/results.

Users can switch detail tabs, expand patterns, checks, plans, saved versions and evaluation results, stop an individual pair, close or minimize the bubble, and read older messages without forced scrolling; a new-update button returns to the latest messages. The bubble stays above the mobile chart toolbar and Trade button. Display polling pauses for hidden tabs and chart replay; it cannot reconstruct all missed movement. Saved server monitoring continues. The embedded native report bridge retains its existing behavior. Chat guidance never creates orders or grants execution authority.

## Phase 6: persistent setup monitoring

The observer evaluates active frozen plans on each received sampled quote as well as every 250 ms, using executable bid/ask and completed execution candles. This preserves brief crossings that could recover before the next timer pass. It does not recover prices absent from OANDA's sampled feed. READY means price is in the entry zone; it does not mean a confirmed signal or recommended trade. The chart shows the measured entry checklist: data/news/spread coverage, executable zone, closed-candle confirmation, entry distance/target, invalidation and entry lifetime. Unpriced watch conditions show that a fresh Analyze is required, rather than manufacturing missing levels. Checks on interrupted connections are labeled unknown. AI interpretations cannot change these conditions.

An observed price invalidation is recorded even when news, spread, context or journal restrictions block a new entry. Paused/nontradeable quotes cannot prove invalidation. A pre-trigger price-feed interruption or server restart discards confirmation; on resume a full new candle must start after resumption. Entry gates such as delayed broker candle delivery, news and spread do not claim a missing price path: they clear previously evaluated confirmation but permit a newly delivered closed candle once checks recover. This distinction prevents each broker candle-refresh delay from restarting the entire confirmation period. Confirmation expires exactly at the end of the following execution interval. Latest closed candles are evaluated by time, regardless of input ordering. Frozen entry, stop, target, zone and original trigger remain unchanged.

Entry expiry applies only to untriggered setups. A triggered hypothetical signal continues until an observed stop/target, interruption, or explicit stop/replacement. Stopping/replacing a triggered monitor closes it with `monitoring_stopped`, preserving its original observed entry and no inferred win/loss. Other replaced/stopped plans expire. Mutations serialize with the same owner/pair advisory lock, flush pending transitions first and save a full final snapshot atomically with the journal event. Failed saves preserve the original frozen hypothesis. Because evaluation is suspended while committing the final snapshot, a failed change resets untriggered confirmation; an already triggered signal closes with an unknown outcome rather than assuming the missing path was observed.

`GET /api/market-observer/journal?instrument=PAIR` returns the latest ten saved versions and sixty events for the authenticated owner and selected pair. The chart loads this archive on demand, shows prior hypotheses/frozen levels and event snapshots, and allows refreshing it. Old events originally saved without a snapshot remain readable. No schema migration beyond 054 is required. The journal is signal evidence, not broker accounting or proof of profitability.

## Phase 7: outcome evidence and causal replay

New triggered signals capture `observer-evaluation@1` measurements within their existing plan JSON and terminal journal snapshot. The collector freezes the engine version, executable entry quote/spread, risk from the observed entry to the frozen stop, and current lean/pressure/pattern context. It records distinct quote counts, maximum favorable/adverse movement and the first interruption. Repeated timer reads cannot increase the quote count. Measurements stop at a terminal outcome and never reconstruct missing prices or backfill excursions for older signals. No additional migration or trade table is needed.

`GET /api/market-observer/evaluation?instrument=PAIR` summarizes up to the latest 1,000 plan versions for the authenticated owner and selected pair. It reports all saved plans, triggered signals, measured targets/stops, interrupted/stopped signals, unfinished signals and excluded legacy/inconsistent records. Quote-based R uses the actual observed entry and terminal executable quote; overshoots are not clamped to an ideal stop/target. Spread is reflected by ask-entry/bid-exit for longs and bid-entry/ask-exit for shorts. Commission, slippage and financing are not modeled. These are hypothetical quote observations, never account P/L or broker fills.

Resolved-only mean R and target rate are labeled explicitly. Outcome bounds include unknown and unfinished measured signals in their denominator; the interval is an optimistic/pessimistic bound, not a statistical confidence interval. The initial no-trade baseline is 0R, with the difference computed only for resolved observations. This does not prove that candle confirmation, patterns or AI add value. Mode, pressure and pattern cohorts are descriptive; pattern groups overlap and manually selected plans create selection bias. No minimum sample count is represented as proof of an edge, and no automatic optimization or execution authority is added.

The chart's **View signal results** loads the report on demand and includes expandable methods and recent signal evidence. Empty cohorts show no measured signals instead of a fake win rate. Results carry their load timestamp and require refreshing; changing pairs or entering chart replay cannot display another pair's live report.

`market-recording evaluate FILE --plan=FROZEN_PLAN.json` replays a supplied saved hypothesis from its original creation time. It uses the same measured lifecycle and received-record order, retains other pairs' rows to detect sequence gaps, simulates expiry/stale-price timer passes, and consumes candles/news only when their records arrive. Existing derived status/confirmation/outcome fields are reset before replay; frozen geometry is validated. An optional cutoff keeps later records out of earlier decisions. A full replay ending before a terminal outcome marks the remaining path unknown, while a cutoff can still show an unfinished signal. It reports record gaps, context/feed failures, clean shutdown and bounded event history. Clean shutdown is not proof of complete market coverage. The replay imports no database, provider or order scheduler. It verifies the supplied plan's mechanism, not historical Analyze generation or strategy profitability.

## Verification and operation

```
npm.cmd --workspace api-server run market-observer:test
npm.cmd --workspace api-server run market-observer:plan-test
npm.cmd --workspace api-server run market-observer:evaluation-test
npm.cmd --workspace api-server run market-state:test
npm.cmd --workspace api-server run market-observer:ai-test
npm.cmd --workspace api-server run market-observer:db-test
npm.cmd --workspace api-server run market-patterns:test
npm.cmd --workspace frontend run observer-chat:test
npm.cmd --workspace api-server run market-recording -- observer data/market-recordings/SESSION.ndjson --instrument=EUR_USD --events
npm.cmd --workspace api-server run market-recording -- evaluate data/market-recordings/SESSION.ndjson --plan=outputs/frozen-plan.json --until=2026-10-12T14:00:00Z --output=outputs/observer-replay.json
```

Run the database check from `api-server`; it uses rollback-only fixtures against the configured database. Replay consumes the original receive order and includes calendar/feed failures, with no AI calls or execution schedulers. `--until=ISO` restricts observations to those available at that receive-time cutoff.

Raw NDJSON recording remains separately opt-in through `MARKET_RECORDING_ENABLED` and `MARKET_RECORDING_INSTRUMENTS`. Use a persistent volume for `MARKET_RECORDING_DIR` in production. The recorder has explicit session/buffer caps and reports incomplete coverage when full; it does not provide unlimited tick storage. Observer plans/events are durable in PostgreSQL even when raw recording is off. Do not mistake the bounded in-memory movement window for a saved tick archive.

Before relying on Monday's observations, check that fresh tradeable quotes arrive, movement windows warm, all timeframes resynchronize, calendar coverage is current, and a saved plan survives reload/restart. Closed-market and synthetic checks verify mechanisms; they do not validate profitability. Collect prospective signal outcomes, spread, interruptions and a simple baseline before changing thresholds or granting execution authority.
